💼 Cyber Glacier — Interactive Personal Portfolio

den-dragonio.github.io/cyber-glacier-resume

About the Project

A personal portfolio / résumé website built entirely from scratch using a pure Vanilla Web Stack (HTML5, CSS3, JavaScript). The decision to avoid heavy front-end frameworks like React or Angular was deliberate — to prevent overengineering, keep the project lightweight, maximize loading speeds, and demonstrate a deep understanding of core DOM manipulation and browser rendering engines.

⚙️ Tech Stack & Architecture

🏗️
Core Stack
HTML5 · CSS3 · Vanilla JavaScript

Zero dependencies, zero build step. Pure browser-native technologies for maximum portability and minimum overhead.

🎨
UI / CSS Architecture
CSS Grid · Flexbox · CSS Variables · backdrop-filter

Mobile-first responsive layout powered by Grid + Flexbox. Glassmorphism aesthetic via backdrop-filter. Color palette managed through CSS Custom Properties.

⚡
JS Performance
requestAnimationFrame · DOM Lifecycle Management

Physics-based background animation driven by requestAnimationFrame instead of setInterval, synchronized with the display refresh rate for smooth 60 FPS.

🚀
Infrastructure & CI/CD
Git · GitHub Pages

Strict version control with Git. Auto-deploy via GitHub Pages — every push to main instantly goes live in production.

🎨 UI/UX & CSS Architecture

  • Glassmorphism Engine: The frosted-glass UI is achieved entirely via the CSS backdrop-filter property — no pre-rendered background images or heavy assets required.
  • Maintainable Theming: All palette values are stored in CSS Custom Properties (variables), making global style changes a single-line edit.
  • Responsive Layout: A mobile-first strategy using CSS Grid and Flexbox ensures the layout scales flawlessly from small phones to wide desktop monitors.

⚡ JavaScript Performance & Memory Management

  • Thread Optimization: The dynamic physics-based background animation is driven by requestAnimationFrame — not setInterval — synchronizing every frame with the hardware display refresh rate and guaranteeing smooth 60 FPS rendering without blocking the main thread.
  • Garbage Collection Handling: A strict cleanup mechanism monitors the lifecycle of every animated DOM element. Once an element moves off-screen, it is immediately removed from the DOM and cleared from tracking arrays — preventing memory leaks and reducing the Garbage Collector's workload.

🧠 Key Engineering Decisions

  • No Framework Overhead: Vanilla stack was chosen deliberately to avoid React/Angular overhead, keeping the bundle at near-zero bytes and page load near-instant.
  • Frutiger Aero Aesthetic: The "Cyber Glacier" Glassmorphism design language was implemented entirely in CSS without any third-party UI libraries.
  • Fluid Animations at 60 FPS: requestAnimationFrame-based loop ensures animations are hardware-synchronized and never cause jank or dropped frames.
  • GitHub Pages CI/CD: Zero-configuration deployment pipeline — pushing to main auto-publishes to production with no manual steps.

💡 E-Svitlo — Real-Time IoT Power Outage Monitor

esvitlo-web.onrender.com

About the Project

E-Svitlo is a full-stack IoT system for real-time electricity outage monitoring and instant Telegram alerts. A physical ESP8266 microcontroller connected to the apartment's home network sends a heartbeat to Firebase every 15 seconds. A Node.js backend continuously analyses these heartbeats and notifies subscribed users via Telegram the moment power goes out or comes back. A responsive web dashboard shows the live status and a Chart.js power availability history.

⚙️ Core Components & Tech Stack

🔌
Hardware Node
ESP8266 · C++ · Arduino IDE

Sends an HTTP PUT to Firebase every 15 s, updating a last_heartbeat timestamp. Acts as a "dumb" scout with minimal failure points.

🔥
Database
Firebase Realtime Database

Single source of truth — stores live heartbeat, state-change history, and user notification preferences.

🟢
Backend Application
Node.js · Express · Telegraf

Polls Firebase every 30 s, calculates durations, handles edge cases, writes history, and dispatches Telegram notifications.

🌐
Web Dashboard
HTML · CSS · Vanilla JS · Chart.js

Responsive, iOS-styled interface. Connects to Firebase via WebSockets for zero-latency updates. Includes Telegram Login Widget.

🏆 Key Engineering Achievements

  • Fault Tolerance & Debouncing: 5-minute threshold logic eliminates false notifications caused by unstable Wi-Fi and ISP packet loss, while maintaining accurate downtime tracking.
  • Decoupled Architecture: The web dashboard reads directly from Firebase, so users see live status and historical graphs even if the Node.js backend goes down temporarily.
  • Efficient State Management: lastKnownStatus is held in memory; precise outage durations are derived by diffing the last hardware heartbeat timestamp against recovery time.
  • Secure Authentication: Native Telegram Login Widget integration — user data is passed to the Node.js API to set notification preferences without a separate password system.
  • Hardware/Software Integration: Bridges low-level C++ network requests (ESP8266) with a modern Cloud/NoSQL environment and a high-level JavaScript application.

⚠️ Technical Trade-offs & Limitations

  • Polling vs. Event-Driven: Polling every 30 s is reliable for an MVP but would generate excessive Firebase reads at scale. Future migration: Firebase Cloud Functions or server-side .on('value') listeners.
  • Free-Tier Infrastructure: UptimeRobot keeps the Render backend awake — acceptable for now but requires refactoring on a dedicated VPS.
  • Hardware "Blind Spot": The ESP8266 cannot distinguish a power outage from an ISP failure. If power is present but the internet drops, the system logs it as an outage.

📝 Conclusion

E-Svitlo demonstrates full-stack development skills and a deep understanding of distributed systems — integrating low-level hardware with modern web technologies, designing resilient cloud architectures, and making pragmatic engineering decisions to deliver a reliable product despite infrastructure constraints.

♟️ Chess Vault Web — Chess Literature Library

chess-lib.onrender.com

About the Project

Chess Vault Web is a responsive web application designed to host and manage a vast library of chess literature. It leverages modern cloud technologies to provide real-time updates and secure access to resources. The UI is built with a mobile-first approach to ensure a high-quality reading experience on any device.

⚙️ Key Technical Processes

🚀
Version Control & CI/CD
GitHub · Render

Repository hosted on GitHub. Render auto-deploys on every commit to main, keeping the live site always up to date.

⚡
Real-Time Data
Firebase Firestore · onSnapshot

A "News" system tracks library updates (new sections A, B, VGD…). onSnapshot listeners reflect changes instantly — no page reload needed.

🔒
Security Architecture
Google Cloud · Firebase Auth · Firestore Rules

API keys restricted to authorized HTTP referrers. Domain whitelisting in Firebase Auth. Granular Firestore rules: public read, admin-only write.

📱
Mobile-First UI
HTML · CSS · Media Queries · Vanilla JS

Built with a mobile-first approach using CSS Media Queries to guarantee readability and usability on small screens.

🧟 Surv2D — 2D Zombie Survival & Base Builder

den-dragonio.github.io/surv2d

About the Project

Surv2D is a retro-styled 2D top-down survival game built from scratch using the LÖVE framework in Lua. It offers high-intensity action where players fight hordes of zombies, construct defenses (walls, gates, automated turrets), forge/enchant equipment, and engage in epic boss battles. The web build compiles the Lua code to WebAssembly/WebGL using love.js to deliver zero-install gameplay directly in the browser, while maintaining full hardware-accelerated 60 FPS performance.

⚙️ Tech Stack & Architecture

🌙
Game Engine
LÖVE (Love2D) · Lua

A fast, lightweight 2D gaming framework. Entire entity component system, collision mechanics, A* pathfinding, and UI are hand-coded in Lua.

🕸️
Web Platform
WebAssembly · WebGL · love.js

Ported to the web via love.js, compiling the LÖVE runtime to WebAssembly and mapping canvas drawing calls directly to WebGL APIs.

⚡
Performance
Static Cache · Canvas Scaling

Optimized asset-loading pipeline. Custom scale-independent layout ensures retro pixel-art rendering stays razor sharp at any aspect ratio.

🛠️
CI/CD & Deployment
GitHub Actions · GitHub Pages

Automated workflow bundles the project assets, packages them into a LÖVE archive, builds the HTML5 player, and deploys it straight to GitHub Pages.

📷 Game Screens

1. Title Screen — Atmospheric pixel art splash screen and main menu.

2. High-intensity Combat — Player defending against hordes of zombies with floating damage numbers.

3. Base Fortification — Fortifying defenses with automated turrets shooting arrows, fences, and campfire healing.

4. Crafting & Forge UI — Managing and crafting weapons, armor, and base structures with copper, wood, and iron.

🏆 Key Features & Achievements

  • Dynamic Base Construction: Drop walls, gates, and automated crossbow turrets to secure your compound against night raids.
  • Complex Entity AI: Advanced A* pathfinding and flocking behavior allow zombie hordes to locate breaches, flank obstacles, and target structures.
  • Deep Gear RPG Progression: Forge copper/iron/mythril gear and unlock powerful stats with passive emblems (combat speed, stamina regeneration, double strike).
  • Cross-Platform Codebase: High performance on WebGL (browser) and absolute portability for native Windows, macOS, and Linux executables.
